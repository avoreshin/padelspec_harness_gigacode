Сгенерируй автотесты: {{args}} (ключ релиза `ASFMSTD-NNNN`, список `id` через запятую либо путь к YAML; флаги `--verify`, `--debug`, `--yes`).

**Тип задачи:** утилита тестировщика, **R1** — пишет только локальные файлы под git. Вне PDLC-loop'а, phase-gate transition не выполняется.

| Флаг | Что делает | Трогает стенд |
|---|---|---|
| — | только генерация | нет |
| `--verify` | плюс `dry-run`: Cucumber отвечает, сматчились ли шаги | нет |
| `--debug` | плюс реальный прогон и цикл починки, максимум 5 итераций | **да** |
| `--yes` | пропустить подтверждение перед реальным прогоном | — |

`--debug` чинит только то, за что отвечает генератор: шаг не сматчился, неоднозначен, синтаксис Gherkin, тип stash-значения, непереданное поле. Провалившаяся проверка (`expected: <X> but was: <Y>`), недоступный стенд и несобравшийся Maven — останов с отчётом: сценарий доехал до проверки, сообщение ушло, дальше не его зона.

Выполни skill `autotest-generator`. Полная спецификация — в `${extensionPath}/skills/autotest-generator/SKILL.md`.

Скрипты, на которые ссылается skill:

```
<SETUP>   ${extensionPath}/scripts/autotest-run.sh        прогон и разбор падений
<CORPUS>  ${extensionPath}/scripts/autotest-corpus.py     описание проекта и поиск донора
```

## Источник — тест-модель, не TMS

Читается `docs/testcases/<release>.yaml`, созданный `/pdls:generate-test-cases`. В TMS сценарии не выгружаются, читать оттуда нечего. Команда работает **полностью offline** — ни Jira, ни TMS, ни VPN.

## Preflight — обязателен

| Проверка | Как |
|---|---|
| Тест-модель есть и валидна | `docs/testcases/<release>.yaml` парсится, `test_cases` непуст |
| Запрошенные `id` разрешаются | каждый найден в файле |
| Проект собирается Maven | `pom.xml` в корне |
| Step definitions есть | `src/main/java/**/stepdefs/*.java` с аннотациями `@Когда`/`@Тогда` |
| Каталог feature есть | `src/test/resources/features/` существует и непуст |
| Runner найден | `src/test/java/**/*.java` с `@CucumberOptions` — нужен `glue` |

Проверка не прошла — **останови работу** и перечисли всё недостающее сразу. MCP-проверок нет намеренно: команда не делает внешних вызовов.

Три места, где легко ошибиться:

1. Step definitions в `src/main/java/`, **не** в `src/test/java/`. С неверным путём preflight отвергнет правильный проект.
2. Feature-файлы, наоборот, в `src/test/resources/features/`. Проверка «каталог содержит `core/`» удалена: **`core/` в проекте не существует**.
3. `bash ${extensionPath}/scripts/test-edit-window.sh open "генерация автотестов <release>"` обязателен: feature-файлы под `src/test/`, и `test-files-protector.sh` заблокирует запись. После генерации — `... close`.

## Описание проекта и поиск аналога

Перед генерацией skill смотрит, есть ли файлы, объясняющие устройство проекта — `docs/testproject.md`, `docs/steps/*.md`, `docs/stashKeys.md`, `docs/tags.md`. Нет — собирает их из кода и корпуса (`autotest-corpus.py docs`); существующие не перезаписываются.

Каждый сценарий пишется **по образцу аналогичного из другого модуля**. Нужна проверка логирования в Kafka для модуля N — сначала ищется такая же проверка у модуля M (`autotest-corpus.py similar`), и она берётся за образец формы: последовательность шагов, приёмы ожидания, имена атрибутов. Данные, ключ TMS и теги — по целевому модулю, а не у донора. Донор называется в отчёте.

## Процесс

1. Preflight.
2. `bash ${extensionPath}/scripts/test-edit-window.sh open "генерация автотестов"` — безусловно; закрыть окно после записи файлов.
3. Разобрать аргументы → путь к тест-модели плюс список `id` (пусто = все).
3a. `autotest-corpus.py describe` — неполно, собрать `docs` и сообщить, что создано.
4. Прочитать YAML. Сценарии с `component.confidence: none` отложить в отчёт, не размещать.
5. Построить инвентарь шагов **до генерации**: аннотации `@Когда`/`@Тогда` — контракт; `ParameterTypes.java` — словарь значений; `docs/steps/*.md` — семантика и колонка «Пример»; glue из `@CucumberOptions` — область видимости. Документация контрактом не является: `docs/steps` пишет `{id}`, которого среди `ParameterTypes` нет, а в `docs/tags.md` отсутствует `@smoke` при 56 вхождениях.
6. Построить индекс feature-файлов: путь, `Функционал:`, **блок `Предыстория:`**, теги, названия сценариев, используемые шаги и **инвентарь имён атрибутов по каждому шагу**; прочитать `docs/stashKeys.md`.
7. Выбрать целевой файл по компоненту. Дописывание в существующий файл — норма; новый файл — редкий fallback. Цели: `asfmstd/st/<компонент>/`, `asfmstd/ift/`, `asfmdo/*`. **Не цели:** `debug/`, `afci/`, `afcore/`, `bigfeatures/`, `pmi/`, `prepare/`.
8. Показать похожие существующие сценарии из целевого файла и счётчик `story_tms_cases`.
8a. `autotest-corpus.py similar "<суть проверки>" --exclude <модуль-цель> --print` — найти донора в других модулях. Дедупликация против тестов, написанных человеком, **невозможна**: связи story↔сценарий в репозитории нет.
9. Сконвертировать шаги. Подставлять значения `ParameterTypes` дословно — «активировать» вместо «включить» не сматчится. Ненайденный шаг **не выдумывать**: вынести в отчёт с ближайшим совпадением, разбором почему не подошло и предлагаемой сигнатурой нового шага.
10. Собрать теги в каноническом порядке: allure-метки → `@gen-<id>` → ключ story → стенд → компонент → библиотека → очистка. `@tmsLink=` **не выставлять**.
11. Тег очистки подобрать по таблице пар и пометить как **предложенный**. Сценарий создаёт сущность, а пара не нашлась — прямое предупреждение: иначе сущность останется на общем стенде.
12. Allure-метки скопировать у соседнего сценария и пометить в отчёте. `functionalArea` не выдумывать.
13. Сверить имена атрибутов в таблицах с инвентарём **этого шага** — шаг может быть найден, а поле под ним выдумано. Не найдено → в отчёт, формулировка «не встречался», а не «не существует».
14. Проверить stash-переменные. Определением считаются **три** места: блок `Предыстория:` целевого файла, шаг выше в самом сценарии, `docs/stashKeys.md`. Предыстория выполняется перед каждым сценарием файла — проверка без неё выдаст ложное предупреждение на каждую переменную. Дополнительно: не переопределять то, что уже даёт Предыстория, и сверить типы значений — отформатированная строка вместо `LocalDateTime` даёт `ClassCastException` при формально корректном сценарии.
15. Идемпотентность по тегу `@gen-*`: совпало — пропустить, разошлось — **не перезаписывать**, вынести в отчёт.
16. Записать файлы. Затем **перечитать их**, собрать теги `@gen-*` и построить отчёт по факту, а не по намерению; расхождение — отдельная строка вывода.
17. Дописать в YAML `feature:` и `custom_fields.Автоматизирован: "Да"` тем блокам, чьи теги реально найдены в файлах.
18. Задан `--verify` или `--debug` — запустить `${extensionPath}/scripts/autotest-run.sh` и, для `--debug`, отработать цикл починки. Без флага шаг пропускается: по умолчанию не запускается ничего.
19. Закрыть окно правки тестов (`test-edit-window.sh close`) и **остановиться**. Коммит не делать.


Отобрать весь релиз одним выражением нельзя — Cucumber не поддерживает префиксные шаблоны в `filter.tags`.

## Next step

**Коммит команда не делает** — ни `git add`, ни `git commit`, ни `git push`. Сгенерированные сценарии черновые: теги очистки предложены, allure-метки скопированы у соседа, часть шагов в отчёте как ненайденные. Проверь `git diff`, прогони `mvn test` по тегам, коммить сам. Недостающие step definitions — добавить вручную, предварительно убедившись, что шаг не приходит из glue-пакетов `ru.sbrf.fraud.at.{core,web,rest}.stepdefs`.
