Собери отчёт о состоянии обвязки: {{args}} (флаги `--release <KEY>` — добавить состояние конвейера тестировщика, `--no-selftest` — не гонять smoke-набор, `--keep-keys` — оставить ключи задач как есть).

**Тип задачи:** утилита обвязки, **R1** — пишет один локальный файл под `docs/harness-reports/`. Вне PDLC-loop'а, phase-gate transition не выполняется. Во внешние системы не ходит и сети не требует.

```
<REPORT>  ${extensionPath}/scripts/harness-report.py
```

## Зачем

Разбор поломки по пересказу теряет ровно то, что нужно: код возврата хука, порядок фаз, точный вид находки, версию бинарника. Команда снимает эти факты сама, одним файлом, и добавляет к нему короткую справку — что внутри и на что смотреть первым делом.

## Что попадает в отчёт

| Раздел | Что несёт |
|---|---|
| `harness` | версия, ветка, HEAD, чистое ли рабочее дерево |
| `environment` | ОС и версии бинарников, включая отсутствующие обязательные |
| `hooks` | привязки из `settings.json` против фактического наличия файлов, `bash -n`, а также хуки, которые лежат, но не подключены |
| `schemas` | итог `validate-schemas.sh all` |
| `selftest` | tier'ы `tests/smoke/run-all.sh` и упавшие кейсы |
| `audit` | счётчики событий, отказы гейтов с количеством, переходы фаз обоих циклов |
| `pipeline` | вердикты `sdd-testcoverage`, `release-readiness`, `autotest-review` и **виды** находок |
| `attention` | что смотреть первым делом, по цене ошибки |

Самая дорогая тихая поломка ловится в `hooks`: `settings.json` показывает гейт включённым, а файла нет — политика не применяется, и заметить это по поведению нельзя.

## Чего в отчёт не попадает

Отчёт — про поведение обвязки, а не про проект. Поэтому в нём нет ни строки из feature-файлов, тест-модели, SDD и описаний задач: находки идут **видом и количеством** (`ac-uncovered × 2`), а не текстом.

Сверх этого работает редактура свободного текста — причин отказов и сообщений об ошибках:

| Правило | Что делает |
|---|---|
| пути | абсолютный путь обрезается до двух последних сегментов: `<abs>/docs/sdd` |
| `email`, `ipv4`, `host` | заменяются меткой вида |
| `pan` | последовательность из 13–19 цифр |
| `token` | строка из 32+ символов алфавита токенов |
| ключи задач | псевдонимы `KEY-1`, `SDD-1`, стабильные внутри отчёта |
| похожие на ключ токены | `AC-3`, `UTF-8`, `SHA-256`, `ISO-8601` остаются как есть: критерий, подменённый псевдонимом, стирает сам диагноз |

Псевдонимы сохраняют связность — видно, что три отказа про одну задачу, — не показывая идентификаторов. Соответствие пишется **отдельным** служебным файлом `*.keymap.json`; к отчёту он не относится.

Счётчик срабатываний каждого правила лежит в самом отчёте (`redaction.replacements`): если правило не сработало ни разу там, где ожидалось, это видно.

## Процесс

1. `python3 <REPORT> --project .` — по умолчанию гоняет и smoke-набор; он идёт минуты, флаг `--no-selftest` его пропускает.
2. Задан релиз — добавить `--release <KEY>`: подтянутся вердикты покрытия, готовности и сверки сценариев.
3. Показать человеку блок `attention` **как есть**. Смягчать нельзя: он и есть результат.
4. Назвать оба файла — отчёт и справку рядом с ним — и, если заводились псевдонимы, сказать про служебный файл отдельно.

Скрипт не падает: то, что не собралось, попадает в `errors` как факт, а код возврата становится `1`.

## Next step
