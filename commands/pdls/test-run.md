Прогони автотесты релиза: {{args}} (ключ релиза `ASFMSTD-NNNN`, список `id` через запятую либо путь к YAML; флаги `--dry-run` — только резолв шагов, `--yes` — пропустить подтверждение).

**Тип задачи:** утилита тестировщика. **R1** для `--dry-run` (ничего не запускается), **R2** для реального прогона: он шлёт сообщения на общий стенд и создаёт там сущности.

```
<SETUP>    ${extensionPath}/scripts/autotest-run.sh          прогон и разбор падений
<PROFILE>  ${extensionPath}/scripts/testproject-profile.py   команда запуска и раскладка
```

## Зачем отдельная команда

Прогон был спрятан внутри `/pdls:generate-autotests --verify|--debug` — то есть выполнялся только вместе с генерацией. В цикле тестирования это отдельная фаза: сценарии могли быть написаны вчера, а стенд подняться сегодня, и «зелёный прогон» — самостоятельный факт, который фиксируется в своде по релизу.

## Процесс

1. Собрать теги: `id` из тест-модели, у которых проставлен `feature:`. Нет ни одного — останов: прогонять нечего, сначала `/pdls:generate-autotests`.
2. Взять команду запуска из профиля (`run_by_tag`). Профиля нет — `/pdls:test-project init`.
3. **Реальный прогон — только с подтверждения.** `AskUserQuestion`: «Прогон отправит сообщения на стенд и создаст сущности. Запускаем?» · «Да» · «Только dry-run» · «Отмена». `--yes` пропускает вопрос, `--dry-run` его не задаёт.
4. `bash <SETUP> dry-run "<теги>"`, затем — если чисто и разрешён реальный прогон — `bash <SETUP> run "<теги>"`.
5. Разобрать `VERDICT` и отдать его как есть.

Отобрать весь релиз одним выражением нельзя: Cucumber не поддерживает префиксные шаблоны в `filter.tags`, поэтому теги перечисляются через `or`.

## Вердикты

| `VERDICT` | Что значит | Что делать |
|---|---|---|
| `clean` | сценарии прошли | фаза `run` пройдена |
| `fix` | шаг не сматчился, неоднозначен, тип stash-значения, непереданное поле | чинится генерацией: `/pdls:generate-autotests <id> --debug` |
| `out-of-scope` | `expected: <X> but was: <Y>` — сценарий доехал до проверки, сообщение ушло | **останов**: дефект продукта либо неверное ожидание в тест-модели. Подгонять сценарий под фактический результат запрещено |
| `infra` | стенд недоступен, Maven не собрался | прогона не было; чинить окружение, статус фиксируется как `not_run` |
| `unknown` | лог не совпал ни с одним шаблоном | отдать человеку, не додумывать |
