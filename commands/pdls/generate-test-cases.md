Сгенерируй тест-кейсы по составу релиза: {{args}} (ключ релиза `UPG-xxxxx` либо ссылка на него; флаг `--apply` — второй проход, запись в Jira).

**Тип задачи:** утилита тестировщика, **R2** — пишет во внешнюю систему, видимую всей команде. Вне PDLC-loop'а, phase-gate transition не выполняется.

Выполни skill `tc-from-release`. Полная спецификация — в `${extensionPath}/skills/tc-from-release/SKILL.md`.

## Preflight — обязателен, до любой генерации

| Проверка | Как |
|---|---|
| Jira MCP настроен и живой | живой вызов `get_project("TAF")` |
| Проект TAF доступен | тот же вызов, в ответе `projectId=66704` |
| Контекст проекта на месте | каталог `docs/harness/modules/` существует и непуст |

Проверка не прошла — **останови работу**, сообщи, чего именно не хватает, и не создавай ничего. Тексты отказов — в skill'е. Работа в деградированном режиме не предусмотрена.

## Процесс

Команда работает в два прохода, между ними — человек.

### Проход 1 (без `--apply`) — черновик в файл

1. Preflight.
2. Извлечь ключ релиза из аргумента или URL. Ключи связанных issue имеют вид `UPG-18405-15` — не предполагать формат `^[A-Z]+-\d+$`.
3. `get_issue()` → релиз, `get_issue_links()` → связанные issues по link type `11400`.
4. Оставить issueType **Story** и **Task**; исключить Bug и Sub-task.
5. Для каждой story: определить компонент по таблице триггеров, определить стенды, прочитать `docs/harness/modules/<component>.md`, сгенерировать 3–10 TC.
6. Записать всё в `docs/testcases/<release-key>.yaml` со `status: draft`.
7. Отдать путь пользователю и **остановиться**. В Jira не записано ничего.

### Проход 2 (`--apply`) — запись в Jira из файла

1. Preflight повторно.
2. Прочитать `docs/testcases/<release-key>.yaml`. Остановиться, если файла нет, `release` не совпадает с аргументом, `status: applied` или YAML не парсится.
3. Создать папку релиза, создать TC батчами по 20 с паузой 1 с, привязать к story.
4. Записать обратно в файл `status: applied` и `key: TAF-Txxxx` в каждый блок.

Генерации на втором проходе нет: создаётся ровно то, что в файле, включая ручные правки человека.

```
Проверь файл, поправь что нужно, затем: /pdls:generate-test-cases <key> --apply
```

```
Дальше: /pdls:generate-autotests TAF-Txxxx,...
```
