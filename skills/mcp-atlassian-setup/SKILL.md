# Настройка MCP-серверов Atlassian

Интерактивный мастер: доводит машину пользователя от «ничего нет» до работающих
серверов `atlassian` и `delta-confluence` в GigaCode.

**Тип задачи:** настройка рабочего места, **R1** — вне PDLC-loop'а, phase-gate
не выполняется, evidence bundle не собирается. Меняются только файлы в домашнем
каталоге пользователя, репозиторий не трогается вообще.

## Что появится на машине

| Что | Где | Как |
|---|---|---|
| Пакеты `mcp-atlassian`, `requests`, `redis` | `~/.venv` (Linux: `<work_dir>/.venv`) | ставятся из внутреннего индекса SberOSC |
| Конфиг npm | `~/.npmrc` | **перезаписывается целиком** |
| Серверы `atlassian`, `delta-confluence` | `~/.gigacode/settings.json` | дописываются, чужие серверы сохраняются |

Про `~/.npmrc` предупреждай отдельно: файл не дополняется, а переписывается. Если
`check` сообщил, что он уже есть — скажи об этом до подтверждения, а не после.

## Инструменты

Вся работа — три вызова оркестратора `setup-mcp-atlassian.sh`. Ниже он
обозначен как `<SETUP>`; конкретный путь даёт команда `/pdls:setup-mcp` — здесь он не
пишется намеренно. Настройку рабочего места запускают сразу после установки
harness'а, до `/pdls:init-project`, поэтому путь через каталог проекта тут не
годится: его ещё не существует.

```bash
bash <SETUP> check     # осмотр, ничего не меняет
bash <SETUP> apply     # значения через окружение
bash <SETUP> verify    # проверка результата
```

Сам JSON не редактируй ни `Write`, ни `Edit`: в `settings.json` лежат чужие
MCP-серверы пользователя, и правка файла текстом их теряет. Слияние делает
скрипт.

## Обращение с токенами

- Токен, который пользователь прислал, **не печатай обратно** — ни целиком, ни
  первыми символами. Подтверждай фактом: `Токен Confluence Sigma принят ✓`.
- Токены передаются в `apply` только через окружение одной команды. Не пиши их
  в файлы проекта, не сохраняй в заметки, не подставляй в примеры команд.
- В файл `~/.giga_sberosc` их кладёт оркестратор под `umask 077` и удаляет по
  `trap` в любом исходе, включая падение установки. Отдельно чистить не нужно.
  Единственное исключение — windows-ветка без bash (шаг 6), там удаляешь сам.
- Если пользователь прислал токены до того, как ты о них попросил — не
  переспрашивай и не проси прислать ещё раз.

## Диалог

Шаги идут строго по одному. После каждого — ждать ответ, не выполнять следующий
шаг заранее и не объединять вопросы.

### Шаг 0 — Осмотр машины

Запусти `check`. **Первая строка вывода — `Платформа: linux|macos|windows`.**
Запомни её: по ней ветвятся шаги 1, 4, 5 и 6. Сам ОС не угадывай и у
пользователя не спрашивай — определение живёт в оркестраторе (`uname -s`), и
он же по нему выбирает платформенный скрипт в `apply`. Тебе платформа нужна
только чтобы задавать правильные вопросы:

| Платформа | Что меняется в диалоге |
|---|---|
| `linux` (SberOS) | шаг 1 — перезагрузка и заявка в «Друге», в сводке venv в `<work_dir>/.venv` |
| `macos` | шаг 1 без Pip и без заявки, venv в `~/.venv` |
| `windows` | шаг 4 (путь к `python.exe`) задаётся только здесь, venv в `~/.venv` |

Дальше разбери остальной вывод:

- `FAIL` есть → останови мастер, перечисли, что чинить. Ничего не меняли.
- Только `WARN` → перечисли и спроси, продолжать ли.
- Чисто → одна строка «машина готова» и сразу к шагу 1.

Отдельные случаи `FAIL`:

| Что сказал `check` | Что говорить пользователю |
|---|---|
| python не найден | «Нужен Python из SUS. После установки на SberOS обязательно перезагрузить компьютер, иначе PATH не обновится.» |
| в `/home/work` нет каталога с табельным | «Похоже, это не рабочее место SberOS. Проверьте, что заявка «Рабочее место SberOS (ПРОМ)» в «Друге» одобрена.» |
| ОС не определена | «Поддерживаются Linux (SberOS), macOS и Windows. Определить текущую не удалось — настройка невозможна.» |

### Шаг 1 — Предустановки

Покажи список и спроси, всё ли стоит. Ставится из SUS:

- Node.js — https://usersoft.sberbank.ru/#program/s/72f9c7d1-6397-4495-905d-68606ecdfc23
- GigaCode Desktop — https://usersoft.sberbank.ru/#program/s/a8c540db-92a2-4c75-804e-1c87e96ca9ec
- Python — https://usersoft.sberbank.ru/#program/s/e7343f32-74e6-4f97-aebf-2ee72b937151
- Pip (только SberOS) — https://usersoft.sberbank.ru/#program/s/7182180f-c708-491f-b6c6-e85a8978ae74

Pip показывай только на `linux`. Там же добавь два пункта: после установки
**перезагрузить компьютер**, и нужна заявка в «Друге» → «Рабочее место SberOS
(ПРОМ)», в обосновании — «Для использования и конфигурирования GigaCode CLI».

`AskUserQuestion`: «Всё установлено?» · варианты: «Да, продолжаем» ·
«Нет, ставлю сейчас — подожди» · «Прервать».

Fallback для рантаймов без пикера — нумерованный список и ожидание ввода:
```
Всё установлено?
  1) Да, продолжаем
  2) Нет, ставлю сейчас — подожди
  3) Прервать
```

### Шаг 2 — Четыре токена

Спрашивай **по одному**, в этом порядке. Для каждого — ссылка и что там нажать.

| № | Токен | Где выпускать |
|---|---|---|
| 1 | Confluence Sigma | https://confluence.sberbank.ru/users/viewmysettings.action |
| 2 | Confluence Delta | https://confluence.delta.sbrf.ru/users/viewmysettings.action |
| 3 | Jira Delta | https://jira.delta.sbrf.ru/secure/ViewProfile.jspa |
| 4 | SberOSC | https://sso.sberosc.sigma.sbrf.ru/dashboard/profile/ |

Для первых трёх подсказка одинаковая: назвать как угодно, **убрать галку**,
создать, скопировать. Повторно посмотреть токен после закрытия окна нельзя —
предупреди об этом до того, как человек закроет вкладку. Для четвёртого — просто
кнопка «Копировать токен».

Проверяй форму ответа, не содержание: непустой, без пробелов внутри, не похож на
URL. Не подошло — скажи, что именно не так, и попроси ещё раз этот же токен.

### Шаг 3 — Почта

Адрес sigma, например `GBukin@sberbank.ru`. Проверь, что похоже на адрес.

### Шаг 4 — Путь к python.exe (только Windows)

Пропусти этот шаг целиком, если платформа из шага 0 — не `windows`. Спрашивай,
**только** если `check` напечатал `venv будет создан`; при `venv уже есть` вопрос
не задаётся — `.bat` его тоже не задаст. Текст подсказки: лежит обычно в
`C:\Program Files\Python313` (цифры зависят от версии);
если папок несколько — брать максимальную; открыть папку, `Shift` + правый клик
на `python.exe` → «Копировать как путь».

### Шаг 5 — Сводка и подтверждение

Покажи, что именно будет сделано, без токенов:

```
Будет выполнено:
  • venv + пакеты mcp-atlassian 0.21.0, requests, redis 7.2.1 → <путь>
  • ~/.npmrc — перезаписан целиком        <строка только если файл существует>
  • ~/.gigacode/settings.json — добавлены серверы atlassian, delta-confluence
    (уже настроенные серверы сохраняются: <перечисли из check>)
Почта: <адрес>
Токенов принято: 4
```

`AskUserQuestion`: «Применяем?» · «Да, применить» · «Отмена». Без явного «да» не
запускай `apply`.

### Шаг 6 — Установка

```bash
SIGMA_TOKEN='…' DELTA_TOKEN='…' JIRA_DELTA_TOKEN='…' SBEROSC_TOKEN='…' \
MAIL_ADDRESS='…' \
bash <SETUP> apply
```

На Windows добавь `PYTHON_EXE_PATH='…'`, если спрашивал на шаге 4. Для ротации
токенов — `apply --tokens-only` и без `SBEROSC_TOKEN`.

Шаг долгий — установка идёт из внутреннего индекса. Упало на `pip install` —
первым делом проверь токен SberOSC: он единственный, который проверяется прямо
здесь, остальные три до первого обращения к Confluence и Jira не валидируются
нигде. Предложи выпустить заново и повторить с шага 2, пункт 4. Не сработало —
причина не в токене: индекс недоступен или для этой версии Python нет колёс
(`--only-binary :all:` запрещает сборку из исходников).

**Windows без bash.** Если `bash` в системе нет, оркестратор запустить нечем.
Тогда напиши файл `%USERPROFILE%\.giga_sberosc` в диалекте `key=value` (без
кавычек, пять строк) и запусти `configure-windows.bat` напрямую — он лежит в
подкаталоге `mcp/` рядом с `<SETUP>`. После этого файл с токенами удали сам — `trap` здесь не сработает.

### Шаг 7 — Проверка

Запусти `verify`. `FAIL` — покажи строки и не объявляй успех:

| Что сказал `verify` | Что это значит |
|---|---|
| интерпретатор не найден | venv создан в одном месте, а в конфиг записан путь в другое. Конфиг валиден, сервер описан, запускать нечего — нужен полный `apply` |
| точка входа не найдена | venv на месте, но `mcp-atlassian` не установился — смотри вывод `pip install` на шаге 6 |
| невалидный JSON | `~/.gigacode/settings.json` испорчен чем-то ещё; повторный `apply` перезапишет его, чужие серверы при этом потеряются |
| не ответил на `--help` (WARN) | пакет на месте, но не импортируется. Не блокирует — предложи проверить руками командой из вывода |

Чисто — итог:

```
✅ MCP Atlassian настроен

Серверы:  atlassian (Confluence Sigma + Jira Delta) · delta-confluence (Confluence Delta)
Конфиг:   ~/.gigacode/settings.json
Проверка: OK <N> · WARN <M> · FAIL 0

Перезапустите GigaCode CLI — серверы читаются при старте.
Дальше можно кидать в чат ссылки на страницы Confluence и задачи Jira.
```

## Повторный запуск

Мастер идемпотентен, лишних вопросов задавать не надо. `check` уже показал, что
настроено; исходя из этого предложи выбор:

| Вариант | Что делать | Что спрашивать |
|---|---|---|
| **Обновить токены** — истёк срок, всё остальное на месте | `apply --tokens-only` | три токена Atlassian и почту; шаги 1 и 4 пропустить |
| **Переустановить** — пакеты побились | обычный `apply` | всё, включая токен SberOSC |
| **Только проверить** | сразу `verify` | ничего |

`--tokens-only` переписывает только `settings.json`, беря пути к venv из него же.
Пакеты, venv и `~/.npmrc` не трогаются, токен SberOSC не нужен — он живёт в
`~/.npmrc` и в индексе pip, а не в конфиге MCP. Если истёк именно он — нужен
полный `apply`.

Обычный `apply` venv **не пересоздаёт**: платформенный скрипт создаёт его только
когда каталога нет, иначе ставит пакеты поверх. Обещать пользователю чистую
переустановку нельзя — если venv нужно снести, это делается руками до запуска.

Аргументы команды: `--verify-only` — сразу шаг 7 и ничего больше;
`--tokens-only` — шаги 0, 2, 3, 5 и `apply --tokens-only`.

## Когда НЕ использовать

- Настроить MCP-сервер, не относящийся к Atlassian, — это не сюда.
- Починить сломавшийся сервер, который вчера работал: сначала `verify`, он
  показывает, что именно отвалилось. Полная переустановка ради диагностики —
  лишнее.
- Настроить окружение не на своей машине. Скрипты пишут в `$HOME` того, кто
  запустил сессию, и другого режима у них нет.
